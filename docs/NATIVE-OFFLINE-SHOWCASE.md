# CookX 原生离线内容分支

本分支 `feat/native-offline-showcase` 独立发布，禁止合入 `main`。界面直接使用正式版 Kotlin / Jetpack Compose 页面，安装名称为 CookX；包名 `com.smartcooking.app.showcase`，与正式版、离线测试版隔离安装和存储。

## 使用

首次启动进入林小厨账号，后续增删改会保留，不会在刷新或重启时恢复初始值。可退出后使用 `lin` 或 `chen` 登录，初始口令均为 `cookx123`。这些账号只存在本机，不是云端凭据。管理员可生成本机邀请码、注册新昵称账号。恢复初始内容请在 Android 应用设置清除本应用数据；操作前导出需要保留的记录。

连接 JDY-31 的方法与正式版相同。没有连接时显示未连接、无实时温度，不自动启用回放。系统语音与 TTS 由手机提供；语音服务不可用时保留按钮和文字操作。

## 内容和真实本机操作

| 模块 | 初始内容 | 本机交互 |
|---|---|---|
| 冰箱、鲜度 | 32 种食材、125 个库存计数，含临期批次 | 增删改、日期清空、小数保质期、回读、识别确认、批次扣减凭证 |
| 菜谱、烹饪 | 22 道现有菜谱＋5 个主食/早餐模板，5 个副本、3 个收藏 | 复刻、收藏、步骤计时、调整确认、完成核对、撤销等沿用正式会话模块 |
| 家庭、采购 | 2 个账号、1 个家庭、8 个共享批次、6 个采购条目 | 邀请、加入、转入、认领、购买、实际入库、共享扣减、退出/移除 |
| 社区 | 6 篇作品、图片、评论及点赞 | 主动发布、编辑、删除、互动、举报、管理员隐藏及榜单 |
| 剩余食材 | 原料和熟食各一条 | 记录、储存/异常/再加热事件、使用量、符合条件时查看菜谱 |
| 成长 | 8 条预置完成记录、挑战和徽章 | 完成事件去重累计、挑战加入及进度、奖励恢复 |
| 七日菜单 | 14 餐预置菜单 | 配置、锁定、重算、保存、复制菜谱、采购生成、价格维护 |

## 与正式服务的差异

- 识别不分析上传图像，返回预置的番茄、鸡蛋、西兰花候选，必须人工确认。菜谱问答选择内置菜谱，不调用大模型。不能据此评价视觉或生成模型效果。
- 家庭和社区在本机账号之间交互，没有跨手机同步，不连接真实用户。图片保存到应用私有目录。
- FreshFusion 的时间与储存分项使用仓库原权重和储存规则在本机计算；V/H 缺测保持 null。附有与 Python 正式服务的固定输入对照测试。不能当作食材实测结果或可食用性鉴定。
- 推荐根据可用库存和明确禁忌匹配内置菜谱，不冒充正式推荐的完整综合分；缺失分项显示不可用。偏好模型只在候选集合内重排。
- 菜单用本机候选组合而非服务端 OR-Tools。不保证最优；未知价格/营养硬约束明确拒绝，不静默放宽。预置菜单供流程浏览，开工前仍须核对库存。
- 偏好学习使用人工准备的起始反馈；真实长期收益未验证。训练评估和后续用户修改均本机执行。
- 应用移除 INTERNET 权限，终止式 OkHttp 拦截器不发出请求。外部地图/外卖入口仍是正式版的外部应用链接，其第三方网络服务不在安装包内。

## 存储与回退

原生页面通过 `ApiClient` 接入 `LocalRuntime`，业务拆为库存/菜谱、家庭、社区/成长、菜单、鲜度和学习模块。写操作在锁内执行，先保存原快照，失败回滚；幂等结果随数据一起同步落盘。账号数据分别保存，成员权限在每次操作重新检查。

正式版只向离线分支单向同步。禁止将此分支或 `feat/p2-local-test-apk` 合入 main。正式分支仍以 PR #49 的 `2d22c81` 为界面基线。回退 APK 版本时须保留当前本机数据备份；不要将本机内容导入真实服务器作为实测记录。

## 构建与验收

在 Android SDK 36、JDK 21 下执行 `android-native/gradlew :app:assembleRelease :app:testDebugUnitTest`。Windows 路径含中文时，先复制 android-native 到纯英文临时目录。不要复制 build/.gradle 或签名私钥到仓库。

测试覆盖本机业务读写、账号隔离、幂等扣减、持久化失败回滚、菜单缺失约束、鲜度对照、无温度生成接口，以及 Compose 页面导航与截图。最终结果、提交及 APK 校验见发布说明。手机安装、蓝牙长连、系统语音和锁屏通知仍需真机确认。
