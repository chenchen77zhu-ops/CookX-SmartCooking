# 剩余食材与熟食记录

原料仅引用个人库存批次，随原库存实时核查 FreshFusion；熟食单独保存制作、首次储存、到期、连续低温条件和事件，不计算 FreshScore。数量未知、条件不明、异常或过期记录保留，但不进入建议。

熟食按用户明确选择的类别提供米饭、面条、蔬菜、熟肉的再利用思路；不猜测食材类别、内部温度或份量换算。缺少类别时仅给处理检查指引。再加热使低温条件需重新确认，不重置任何原时间。异常标记不可通过恢复储存解除。

参考 USDA《Leftovers and Food Safety》：https://www.fsis.usda.gov/food-safety/safe-food-handling-and-preparation/food-safety-basics/leftovers-and-food-safety 。本版采用一小时内低温储存的保守工程筛选（覆盖高环境温度限制），冷藏达到四天排除；用户到期时间更早时按更早值。筛选不是可食用性鉴定。内部约 74 ℃再加热核验需要食品温度计，不能用 MLX90614 锅面读数替代。

接口 `/api/v3/leftovers` 与 `/{id}/events`、`/{id}/ideas`。所有数据按登录账号隔离，事件使用版本和操作凭证。原料使用仍在原库存核对；熟食实际使用量单独记账。

验证：3 项真实 SQLite/API 场景（未知/异常/过期、再加热时间保留、重复使用凭证、越权、原批次删除），移动浏览器新增未知记录→禁止建议→结束保留记录，前端构建通过。待真实烹饪验证；无可食用性保证。
