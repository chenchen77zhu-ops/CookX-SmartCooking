# JDY-31 扫描修复（本地测试版）

用户报告：拯救者手机，本地测试版一直显示“正在扫描附近的 JDY-31”；系统蓝牙能够配对。尚未获取手机日志，不能断言这是唯一故障原因。

已修复的软件缺口：

- Android 13+ 的蓝牙广播接收器改为 `RECEIVER_EXPORTED`。仅监听四个 Android 蓝牙系统 action，不接收自定义 action。Android 官方说明蓝牙进程使用独立的高权限 UID，`NOT_EXPORTED` 可能丢失其广播。[广播说明](https://developer.android.com/develop/background-work/background-tasks/broadcasts)
- 每次扫描先读取已配对设备并显示；原生返回设备快照，避免页面监听建立时序造成列表丢失。已配对仅表示有配对记录，不保证在线，更不表示已经建立 SPP 连接。[已配对设备说明](https://developer.android.com/develop/connectivity/bluetooth/find-bluetooth-devices)
- 新增 25 秒主动截止，扫描开始失败、取消、正常结束都收尾；旧扫描超时不能终止新扫描，迟到的 STARTED 广播不能将已连接状态改成扫描中。
- 保留扫描启动结果、结束原因和设备发现记录；导出诊断时重新获取 Android 版本及权限等信息。
- 同一测试包名，版本提高为 `1.0.1-localtest-btfix` / versionCode 2，使用原有调试签名。可直接覆盖安装上一版本，无需卸载和清除测试数据。

分支：`fix/localtest-jdy31-discovery`，基于 `2871295`；仅本地，不上传、不合并远端。温度算法、硬件固件、库存和示例接口未修改。

验证：前端 63 项单元测试通过；本地版完整浏览器回归通过；另新增 3 项原生扫描生命周期 JVM 测试，结果随 Android 构建记录。浏览器和 JVM 均不等于实际无线扫描验收。

手机复测：

1. 覆盖安装新版，打开“CookX 本地测试”，允许“附近设备”。保留系统 JDY-31 配对记录。
2. 给模块供电，在 AI 厨房打开“设备状态与诊断→扫描与连接设备”。应能看到标注“已配对”的 JDY-31；无需等扫描结束，可选中后连接。
3. 列表存在并不证明设备在线；连接后检查是否收到连续温度。附近扫描最迟约 25 秒结束。
4. 如果仍失败，导出设备诊断 JSON。需要分别记录“列表没有设备”“有设备但连接失败”“连接成功但没有温度”，不要反复解除配对、烧写固件或重装清数据。

真实拯救者手机扫描/SPP/持续测温尚待用户复测，本记录不宣布硬件验收通过。
