# CookX 本地测试版说明与功能对照

## 这个版本是什么

本地分支 `feat/p2-local-test-apk`，从人员二完整功能链 `57ef203` 创建。按要求仅保留本地，不推送、不建 PR、不合并远端 main。原版接口仍保留；只有 `build:localtest` 将 API 调用接到手机本地存储，未知接口直接报错，不回退到网络。

安装后显示 **CookX 本地测试**，包名 `com.smartcooking.app.localtest`，可与原版同时安装，数据互不影响。无需启动 Python、数据库、服务器或配置 API 密钥。库存与记录使用 WebView 本地存储；卸载或清除应用数据会丢失测试记录。该调试 APK 仅用于本地功能测试。

## 使用顺序

1. 打开即进入测试账号 A。顶部展开“本地测试工具”，可切换 A/B 或重置当前账号；另一个账号不受影响。
2. “冰箱”预置正常、临期、过期且零分、部分证据、全部未知及同名多批次示例。新增/编辑名称、数量、储存、日期、小数保质期，清空可选字段并保存，重新打开核对。
3. “载入识别示例”进入确认页，修改后入库。这里没有拍照识别；固定示例不会分析图片。确认后回库存，点击智能推荐查看固定演练卡片。
4. 进入 AI 厨房，点击“载入演练菜谱”，再“开始指导”。四步演练无需点火，可测试计时、刷新恢复、文字指令、麦克风、过咸等调整与撤销。系统中文语音包/识别服务不可用时用文字与按钮；系统服务是否联网由手机决定。
5. 顶部可选择下一次菜谱 JSON 错误、空步骤、业务失败、超时，检查错误与重试；也可选“扣减成功但响应丢失”，完成演练时勾选鸡蛋扣减，再点“核对扣减结果（不重发）”。同名土豆批次不允许自动扣减。
6. 温度区“算法与记录”支持随包提供的仿真回放和实验模型。真测温入口保持原样，可连接 JDY-31；回放与真实数据始终分开。通知需手动开启并授予系统权限。

固定鲜度值和权重只用于展示状态，不运行 FreshFusion；编辑或新增后鲜度为数据不足，不根据字段伪造评分。推荐不执行真实排序，菜谱为操作练习而非实际烹饪配方。库存本地新增保留独立行，不模仿未定的后端批次归并。库存扣减仍采用名称唯一时数量减一的既有语义。

## 构建与证据口径

`npm --prefix frontend run test:localtest`；`npm --prefix frontend test`；`npm --prefix frontend run build:localtest`。浏览器运行 `frontend/scripts/browser-localtest.cjs`，默认预览端口 4175，可用 `COOKX_BASE_URL` 指定。浏览器无 API 响应替身，使用包内同一本地适配器；拦截 API/外网，只允许静态资源，并在页面已加载后关闭网络测试推荐。

Windows 构建：`frontend/scripts/build-localtest-android.ps1 -OutputDirectory <交付目录>`。需 Node、JDK21、Android SDK；脚本在独立 ASCII 临时目录修改测试包身份，不修改原版包名。`build-manifest.json` 记录源码提交、是否未提交、SHA256 与构建时间。脚本支持现成工具链环境变量，也兼容仓库本机工具路径。

自动测试、浏览器桌面移动视口、Android 编译分别记录；不能当作手机安装、真实语音识别、通知投递或硬件精度已通过。温度模型与算法未改动，原实验结论继续适用。
