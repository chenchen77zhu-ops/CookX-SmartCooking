# 七日菜单：独立约束优化

菜单模块保留原 22 道菜和单餐推荐公式，新增独立规划元数据、4 个主食和 3 个早餐模板。每餐主菜+主食，API 支持逐餐可选配菜，页面可统一添加。默认七天午晚餐，可勾选早餐及删去餐次。按实际人数×份量系数缩放原料；原 22 菜模板设为两人份、新模板一人份，属于明确展示并要求确认的工程估算。

OR-Tools CP-SAT（9.15.6755、单工作线程、固定种子）先满足忌口、素食限制、角色、时长、难度、主菜/配菜重复次数、指定菜、预算、营养上下限；主食不受菜品重复次数限制，页面注明。顺序优化临期库存利用、原单餐分、数据完整时的补购成本，最后补足同单位库存利用。前一阶段证明最优才固定其值进入下一阶段。返回最优/可行/无解/超时/数据不足，未证明全部阶段最优时只标可行。

数量按千分之一原单位建模，营养按千分之一单位保守取整上下界；返回后再次从菜谱逐项核算约束及批次占用。同批次跨餐总分配不超过库存，按预计用餐时间重新计算现有 FreshFusion，排除未知、高风险、过期批次。不同单位不擅自换算，旧库存计数不换成克。周预算为全部食材估算成本；补购成本仅扣除同单位有效库存，缺价格为未知而非零。

营养源：USDA FoodData Central SR Legacy April 2018，https://fdc.nal.usda.gov/download-datasets/ 。38 个原料样品记录含 FDC ID、每百克数据、原始份量、来源链接和压缩包 SHA256。抽取脚本 research/planning/extract_usda.py 可重建；豆瓣酱、可乐、泡发木耳缺少直接对应记录，保持缺失，启用营养硬约束时相应菜谱不可选。通用食材、份量及油品映射需用户确认，仅用于原料营养估算，未校正熟制损耗，不能代表全天达标或实际食物检测。

价格按用户保存（元/明确单位，最多四位小数），支持版本冲突。预览保存完整约束、求解阶段、证据及库存版本；保存不扣减/预留库存，不下单。局部替换加载原计划并锁定其他位置，生成独立新计划。执行前重读鲜度及库存；家庭菜单采购要求范围一致且快照未变，改变后须重算。

接口：/api/v3/planning/catalog、prices、preview、menus、menus/{id}/check；复刻源新增 menu，并保留原菜单、份量和库存范围。库存扣减沿现有完成核对入口，家庭计量扣减在最终闭环联调中补齐。

验证：5 项真实 API/求解器场景覆盖价格缺失、无解、超时、忌口锁定冲突、21 餐/配菜、营养/预算再核算、单位不兼容、过期库存、重复占用、权限、保存不扣减和快照变化。移动浏览器缺价格→14 餐预览→明确保存→执行核对→菜谱复刻通过。全量后端 386 项通过。

实验 docs/planning-experiment-results.json 保存固定配置、人工价格夹具、六类结果及重复运行一致性。基线重复最高单餐分违反周重复限制；这是约束层有效性检查，不证明真实营养效果或用户偏好收益。求解依据：https://developers.google.com/optimization/cp/cp_solver 。
