# CookX 多人协作与算法升级：设计及软件验收

## 摘要
本轮将原单人烹饪流程扩展为适合小范围多人内测的系统，完成文档四组暂缓任务的 13 项功能。采用本机或局域网后端，无需先购买公网服务器；账号、库存、凭证和新增业务统一存入 SQLite。原 FreshFusion、单餐推荐公式与温度算法保持不变。

## 方法与实现
首先验证识别确认、库存编辑、鲜度、推荐、烹饪和批次扣减，再按独立分支开发家庭共享、共同采购、菜谱复刻、晒菜、评论、点赞、热门榜、剩菜改造、成长、挑战、徽章、七日菜单及长期偏好学习。

一致性以事务、版本检查和幂等凭证保障。个人与家庭库存分开，转入需确认；家庭采用明确单位和实际数量，不猜测“个”与“克”的关系。购买与入库分步，完成烹饪与扣减结果分别记录。登录会话可撤销和过期，家庭退出后立即失去权限，私人头像与语音经授权读取。

菜单采用独立 CP-SAT 模型，先满足所选餐次、人数、忌口、预算、时间、营养及锁定菜等硬约束，再依次优化临期利用、原单餐分和可靠补购成本。公开营养数据保留来源，价格由用户维护，缺数据不补零，无解不静默放宽。保存后重新核对库存时效及偏好。

个性化排序由用户主动开启，使用明确正负反馈训练正则化逻辑回归。按时间划分测试，评估通过后仅重排原有合格候选；缺数据、模型失败或关闭时回退。原料剩余与熟食剩菜独立建模，不用锅面温度判断可食用性。

## 验收结果与边界
398 项后端、71 项前端及 3 项温度研究测试通过；22 组浏览器检查分别通过，Android 构建与单元检查通过。双账号实际 SQLite 流程覆盖家庭采购至菜单、复刻、扣减、社区和反馈。故意丢失一次扣减响应，原凭证重试后 100.5 克库存仅扣一次 75 克，回读为 25.5 克。

13 项软件功能均已对应交付，功能分支及修复 PR 保留，可追溯回退。离线测试分支独立上传，永不并入 main；其样例不能证明真实多人同步或服务端算法效果。云视觉/菜谱测试使用替身，系统语音、锁屏提醒、持续蓝牙与真实烹饪仍待手机验收。人工实验只证明算法链路可复现，长期收益需要真实用户反馈，未宣称实际识别率或获奖结果。
