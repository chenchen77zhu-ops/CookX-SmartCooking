# 库存接口 v2（人员二补齐）

基线：owner main bd02523；评分公式、推荐权重与温度算法未修改。

- `POST /api/inventory/consume`：`user_id`、稳定 `idempotency_key`、`items: [{item_id, quantity, expected_quantity}]`。数量必须为正整数。按 ID 扣减，整批校验，库存变化返回 409。
- `GET /api/inventory/consumption/{key}?user_id=...`：查询原扣减凭证。相同键与相同清单返回原结果，不重复扣减；相同键换清单返回 409。
- 凭证与库存使用同目录持久日志和进程间文件锁。写入意图后中断，下一次库存操作先恢复该意图。响应丢失须查询原键，不能生成新键重试。备份时须同时保留库存和凭证文件。
- 编辑 canonical 字段时删除相应旧别名，显式 null 不再被旧购买/储存字段回填。未修改的原始日期字符串保留。
- 小数保质期不截断；购买/到期日期继续参与既有批次键。旧名称扣减接口对同名多批次拒绝执行。
- 识别确认继续使用主人 `/api/inventory/confirm-recognition`；不复制或修改 FreshFusion。

验证：345 项后端测试通过，包括重复提交、并发同键、中断恢复、过期数量、批次隔离、小数与旧字段清空。仅针对本地文件存储；不提供多主机共享网络文件系统事务保证。
